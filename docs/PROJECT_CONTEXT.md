# 프로젝트 맥락

최초 구조 정리: 2026-10-12. 사용자와 기획 대화에서 나온 내용을 다음 개발 환경에 전달합니다.

## 제품 목표

주인이 없는 동안 반려견이 혼자 또는 다른 보호자와 어떻게 지냈는지 귀가 후 사진일기로 확인합니다. 결과물은 하루에 일기 한 편이며 사진 여러 장을 포함할 수 있습니다. 강아지 1인칭 말투를 사용합니다.

장기 구상은 카메라와 심박 센서가 있는 목걸이입니다. 심박 변화로 기록할 순간을 찾고 사진 또는 짧은 영상을 촬영합니다. 영상에서는 대표 프레임을 골라 일기에 사용할 수 있습니다.

## 사용자 학습 목표

사용자는 Java / Spring Boot에 익숙합니다. AI를 코딩 보조에만 사용하지 않고 서비스 내부에 적용하는 경험을 원합니다.

- 모델을 배포하고 추론 API로 제공하기
- Spring Boot와 Python AI 서비스를 연동하기
- 이미지·시계열 데이터 수집, 전처리, 저장 파이프라인 만들기
- 추론 작업 상태, 실패, 재시도, 처리 시간 관리하기
- 모델·프롬프트 버전과 사용자 수정 데이터를 관리하기

온디바이스 AI는 초기 아이디어였으나 현재 핵심 목표가 아닙니다. 서버 추론으로 시작합니다. RAG·파인튜닝은 필요성과 데이터가 확보될 때 추가하는 후보입니다.

## 확인된 방향

- 팀은 사용자 포함 2명입니다.
- 목표 기간은 2026년 말까지를 생각하고 있으나 확정 일정은 아닙니다.
- 웹부터 시작하고 앱은 나중에 고려합니다.
- 서비스 백엔드는 Spring Boot, AI 서비스는 FastAPI를 생각하고 있습니다.
- 실제 강아지 확보가 어려워 사람 데이터나 가상 데이터로 먼저 흐름을 검증합니다.
- 하드웨어를 기다리지 않고 사진·영상이 수집되었다고 가정해 개발할 수 있습니다.
- 사용자는 백엔드, AI API·배포를 맡고 팀원은 임베디드·AI 튜닝 쪽을 고려합니다. 정확한 분담은 미정입니다.

## 장비와 미정 사항

학교 장비 또는 로컬 GPU 사용을 고려하며 사용자가 기억하는 사양은 “5060 Ti, 12GB 정도”입니다. 정확한 모델명과 VRAM은 확인되지 않았으므로 가정하지 않습니다. 필요하면 가벼운 Colab 실험도 고려합니다.

아직 정하지 않은 항목:

- Java/Python 버전, Maven/Gradle, 프런트 프레임워크, DB, 파일 저장소
- 사진 해석 모델, 글 생성 모델, 직접 호스팅할 모델 범위
- 팀원의 튜닝 대상과 모바일 담당
- 목걸이 기종, 심박 측정 방식, 촬영 빈도, Wi-Fi/Bluetooth 등 전송 방식
- 발표/평가/포트폴리오 목적, 주당 투입 시간, 서버 예산
- 일기의 사진 수·분량, 품종·성별·성격에 따른 말투 설정

## 검증의 한계

사람 데이터는 수집·시간 연결·추론 호출·일기 저장 흐름을 검증하는 데 사용합니다. 강아지 감정 인식 모델의 학습/검증 데이터로 그대로 대체하지 않습니다.

심박 증가만으로 감정의 긍정/부정을 확정하지 않습니다. 사진·영상에서 상황을 해석하더라도 감정은 추정입니다. 목걸이 시점에서는 강아지 표정·자세가 보이지 않을 수 있습니다.

심박 변화 후 촬영을 시작하면 원인 장면을 놓칠 수 있습니다. 주기적 촬영과 이벤트 촬영을 함께 쓰는 방법, 영상 버퍼 등은 나중에 실제 기기 조건에서 검토합니다.
