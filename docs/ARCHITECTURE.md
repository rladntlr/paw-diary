# 초기 구조와 책임

아래는 구현 전 설계 방향이며 API 계약과 기술 선택은 아직 확정되지 않았습니다.

## 처리 흐름

```text
웹: 사진 + 촬영 시각 업로드, 일기 생성 요청
  -> Spring Boot: 데이터 검증·보관, 생성 작업 관리
  -> FastAPI: 사진별 상황 분석 -> 하루 일기 생성
  -> Spring Boot: 분석 결과·일기·실행 정보 저장
  -> 웹: 진행 상태 및 완성 일기 조회
```

초기에는 직접 HTTP 호출로 연결해도 됩니다. 이후 웹 요청에는 작업 ID를 반환하고 별도 실행 경로에서 AI를 호출하는 방식으로 확장합니다. 작업 큐와 워커 기술은 부하와 요구가 확인된 후 선택합니다. 메모리에서만 작업을 관리한다면 재시작 시 유실 가능성이 있으므로 구현 단계에 맞게 문서화합니다.

## Spring Boot

기본 패키지 제안: `com.pawdiary`.

- `global/config`: 서비스 설정
- `global/error`: 예외 및 오류 응답
- `domain/pet`: 반려동물 프로필
- `domain/record`: 사진·심박·촬영 시각·데이터 출처
- `domain/diary`: 생성 작업과 일기
- `integration/ai`: AI API 클라이언트와 연동 DTO

각 도메인의 controller/service/repository/entity/dto는 실제 기능 구현 시 만듭니다. 빈 클래스는 미리 만들지 않습니다. 인증 관련 도메인은 필요 시 추가합니다.

## AI 서비스

- `app/api`: 내부 추론 API
- `app/schemas`: 입력·출력 형식
- `app/services`: 분석·생성 처리 흐름
- `app/inference`: 모델 로딩과 추론
- `app/core`: 환경 설정
- `experiments`: 모델 검증용 작은 실험

실험에서 확인한 모델을 추론 서비스에 붙입니다. 관찰 결과를 구조화한 뒤 일기 생성에 전달하면 분석 오류와 생성 오류를 구분할 수 있습니다. FastAPI는 서비스 회원/일기 DB를 직접 관리하지 않는 방향으로 시작합니다.

## 데이터 설계 시 보존할 정보

- 기록 ID, 대상 ID, 촬영·측정 시각 및 시간대
- 출처: 사람 / 강아지 / 가상, 실제 기록인지 시뮬레이션인지
- 원본 파일 참조와 분석에 사용한 기록 ID
- 심박 원본 값·단위·측정 품질 정보(제공되는 경우)
- 사진별 관찰 사실과 감정 추정의 구분
- 생성 작업 상태, 오류, 시도 횟수, 처리 시간
- 모델 ID·버전, 프롬프트 버전, 사용자 수정 전후 결과

첫 작업 상태 후보는 `PENDING`, `RUNNING`, `SUCCEEDED`, `FAILED`입니다. 재시도 시 같은 일기가 중복 저장되지 않도록 구현 단계에서 기준을 정합니다.

## 이후 확장

심박 기반 장면 선택 -> 짧은 영상과 프레임 선택 -> 실제 기기 업로드 -> 앱 연동 순서로 검토합니다. 과거 일기를 의미로 검색하거나 생성에 참고할 필요가 생기면 RAG를 검토합니다.
